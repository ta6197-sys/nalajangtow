# 화면별 기능 명세 — Docktimize 선박 스케줄러

## 0. 적용 범위

대상: 사용자가 제공한 선박 스케줄러 화면 3개만 포함.

공통 네비게이션(관찰된 메뉴):
- **선박 스케줄러**: 상황 확인 / 후보 비교 / 확정·보고서
- **정산팀**: 체선료 현황 / 선박별 근거 / 분쟁 점검 *(측면 메뉴로만 표시; 본 추출본의 상세 범위 밖)*

공통 헤더의 관찰 요소: Docktimize AI, SK Energy, Ulsan Terminal, 10/29 13:40 KST, 추천 대기 2건, 사용자/운영팀 표시.

## 1. 상황 확인

**화면 제목:** `10/29 오후~10/30 접안 순서 정하기`

### 표시되는 정보
- 변경 조건: 기상 변화, NORTH CAPE ETA 변동, SK6 관련 일정 변화 등. 세부 수치 일부는 낮은 해상도로 판독 제한.
- 가용·추정 조건: 선석/탱크/설비·날씨 관련 조건 및 사용 가능 상태.
- `앞으로 24시간 · 기상과 시간 제약`: 시간대별 그래프. 위험 시간대를 색상으로 구분.
- `대상 선박 5척`: 선박, 도착·ETA, 배정 선석, 예상 작업시간, 주의사항 중심 표.
- 표시 선박: PACIFIC ROSE, BLUE MARLIN, NORTH CAPE, HANA SPIRIT, GULF PEARL.
- 하단에서 최적화/후보 비교 단계로 이동하는 CTA.

### 사용자 의도 및 기능(화면에서 추론)
- 운영자가 현재 제약과 ETA 변동을 검토한 뒤 일정 재계산 후보를 비교하도록 유도.
- 화면 정보가 어떻게 계산되는지, 데이터가 실시간 업데이트되는지는 캡처만으로 확인 불가.

## 2. 후보 비교

**화면 제목:** `10/29 오후~10/30 접안 순서 정하기`

### 후보 요약 카드

| 비교안 | 화면상 예상 총 체선료 | 기존안 대비 | 화면상 부가 정보 |
|---|---:|---:|---|
| 후보 1 (최소 비용) | $39k | -$22k | 강풍 장기화 시 급증 위험 |
| 후보 2 (추천·균형 비용) | $42k | -$19k | 안정도 1위, 야간 접안 집중(1건) |
| 기존안 (도착순/FIFO) | $61k | 기준 | 낮은 위험(비용 확대) |

모든 비교안 카드에 **제약 위반 0건(충족)**으로 표시됩니다. 후보 2는 주황색 테두리로 추천 강조.

### 타임라인
- `접안 타임라인 (후보 2)` / `48시간 전망`.
- 가로 시간축: 10/29 정오부터 10/31 아침까지 여러 시간 눈금 표시.
- 선석 행: `2Buoy(원유)`, `SK8(제품)`, `SK7(제품)`, `SK6(제품)`.
- 선박 바: PACIFIC ROSE (체선 11h), GULF PEARL (정상), NORTH CAPE (체선 6h), BLUE MARLIN (정상), HANA SPIRIT (정상).
- `부이 마감 14:40` 표시.
- `기존안과 비교` 선택 박스, `후보 시 선박별 상세 표시` 관련 안내, `이유 3가지 보기` 영역.
- 하단: 현재 선택 후보, 예상 체선료 `$42,000`, 절감액 `-$19,000`, `확정하러 가기`.

### 사용자 의도 및 기능(화면에서 추론)
- 복수 안의 비용·위험·제약 위반·선박별 작업 순서를 비교하고 후보를 선정.
- 타임라인의 실시간 드래그 수정, 선택 이벤트, 상세 팝업 등의 실제 구현 여부는 이미지에서 확인되지 않음.

## 3. 확정·보고서

**화면 제목:** `접안 순서 확정 및 공유`

### 좌측: 확정 전 확인 (후보 2)
- 단계 1 확인 / 단계 2 보고서.
- 화면상 마감: `15:00까지`, `1시간 20분 남음` (디자인 예시 값).
- 주의 필요 **2건**:
  1. `날씨 급변 · 강풍 시작이 앞당겨질 수 있음` → `HANA SPIRIT 내일 07:00로 연기 대응 준비`.
  2. `저장 탱크 여유율 18% · 저장 한계 도달 가능` → `출하팀 실시간 공유 및 모니터링 유지`.
- `문제없는 항목 2건` 접이식 영역.
- `확정 사유 (선택)` 기본값: `현장 안전 및 VLCC 우선 접안 (기본값)`.
- `후보 2로 확정` 버튼.
- 확정 시 다음 단계 보고서가 활성화되고 정산팀 및 부두운영팀에 즉시 전송된다는 **화면상의 설명**이 있음. 실제 전송 기능 동작은 미검증.

### 우측: 보고서 초안
- `AI 자동 구성` 표기.
- 메일 제목 예시: `[Docktimize] 10/29 울산 원유부두 접안 순서 확정 안내 (후보 2)`.
- 이유: `22시 강풍 전 VLCC(PACIFIC ROSE) 선제 접안으로 도착순 대비 체선료 $19k 절감`.
- 비교 결과: `후보 2 ($42k) vs 후보 1 ($39k) vs 도착순 ($61k)`.
- 남은 리스크: 강풍 조기 발생 시 HANA SPIRIT 익일 순연 대응 준비.
- 기능 표시: `보고서 전문 보기`, `보고서 복사`, `Report 내려받기 (PDF/Excel)`.

## 4. 기본 흐름과 구현 검증 포인트

1. 상황 확인 → 영향 요소와 대상 선박 파악
2. 후보 비교 → 비용 및 리스크를 비교하고 후보 2 선택
3. 확정 전 위험 확인 → 경고 2건과 대안 검토
4. 확정 사유 선택 → `후보 2로 확정`
5. 보고서 확인·복사·내보내기

**구현 시 추가로 정의해야 하는 사항(캡처에는 없음):** 제약 계산 근거, 실제 ETA 갱신 주기, Freeze Window, 일정 수정 권한, 선석 점유 종료 규칙, 확정 이후 재스케줄 정책, 보고서 실제 수신·전송 로직, API 연동.

이 추가 사항은 원본 디자인에 있다고 주장하지 않으며, 개발 단계에서 별도 정의가 필요한 항목입니다.
