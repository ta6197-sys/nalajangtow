# V5 최적화 품질 감사 — 1차 S5 작업 명세

## 1. 배경

현재 main에는 `INTEGRATED_COST_AWARE_V1` 경로가 있으며, CP-SAT이 유한 ETB·선석 후보를 선택하면서 체선료(정수 USD 센트) 목적함수와 정확한 탱크 이벤트 재고 제약을 함께 적용합니다. 72시간 계획/24시간 Rolling, 동적 ETA-5시간 잠금, 물리·재고·계약 비용 독립 재검증 기능도 존재합니다.

따라서 이번 작업은 새 스케줄러 개발이 아니라 **실제 데이터로 실행되는지 증명하기 위한 검증 게이트**입니다. 이전 PR의 합성 fixture PASS를 실제 V5 전체 성공으로 취급하면 안 됩니다.

## 2. 단계별 점검

| 순서 | 실제 검증 | 정상 판정 |
| --- | --- | --- |
| 1 | 소스 4개 원본 파일·해시·정규화 | 140항차, 11선석, 3탱크, FIX 15건, preflight PASS |
| 2 | 명시적 도선·운영정책 입력 | 빈 값/미확정 예외가 있으면 명시적 차단, 임의 기본값 불허 |
| 3 | 기존 비용·탱크·Rolling 테스트 | PASS/FAIL/ERROR/SKIP 실제 실행 수 보고 |
| 4 | 기존 통합 비용 최적화로 S5 실행 | 5항차·2창, 적어도 하나의 비어있지 않은 창 |
| 5 | 체크포인트·목적함수 수치 감사 | FIX 고정·ETA 순서·선석·계약별 센트 합 일치 |
| 6 | 원본 기반 Stage-4 Resume 독립 Replay | 물리·재고·정산·상태 이월 재실행 PASS |
| 7 | 실패 분류 | 입력 / 물리 / 탱크 / 계약 / 후보탐색 / 제한시간 / Rolling 구별 |

## 3. 중요한 제한

- S5 부분 시나리오에서는 선택된 5항차 밖의 135항차가 만드는 실제 선석/재고 충돌을 모델에 넣지 않습니다.
- `OPTIMAL`은 해당 72시간 창의 **생성된 유한 후보 영역**에서만 성립합니다. 58일 전체 및 연속시간 모든 ETB에 대한 최적성은 검증하지 않습니다.
- 72시간 창이 겹치므로 창별 예상 체선료를 합쳐 누적 체선료로 쓰지 않습니다.
- 실제 합성 V5의 계약 정산에서 과거 자료와 달랐던 40개 Clock Start 항차, 4-1/4-2, 02:00~08:00 접안, low-GRT/deep-draft, 이안 도선 정책, 58일 외부유량 마지막 커버리지 등 미확정 사항은 별도 차단 원인이 될 수 있습니다.
- 비용 `null` 또는 미해결 계약은 0달러로 치환할 수 없습니다.
- 새 검증 모듈의 정수 센트·FIX·ETA 감사는 독립 선박 물리 모델이 아닙니다. 신뢰 가능한 물리·재고 재계산은 기존 Stage-4 Replay를 사용합니다.

## 4. 산출물

`run_id`, 원본 지문, 소스 개수, S5 창별 선박 수, FIX 및 ETA 위반 여부, 창별 비용 센트, 합계 산술 동등성, CP-SAT 솔버 상태/유한영역 증명 여부, 누적 비용의 의미, 독립 Replay PASS/FAIL과 오류 코드가 포함된 JSON 감사 결과.

DB 테이블 생성·수정·적재, UI 연결, 추가 후보 최적화 개발, 전체 140항차 실행, A/B/C 추천안 구현은 이번 단계에서 제외합니다. 첫 재현 가능한 실패를 확보한 후 최소 수정 대상을 분리해서 차기 작업으로 진행합니다.
