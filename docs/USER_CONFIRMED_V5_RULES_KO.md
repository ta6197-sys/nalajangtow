## 1. 프로젝트 목표와 엔진 아키텍처

### 1.1 [확정] 목적

**전체 선박의 계약상 체선료를 최소화하면서, 선석·접안·하역·탱크 재고 및 운영 제약을 만족하는 실행 가능한 스케줄을 생성한다.**

- 최적화 결정: 선박별 **선석 배정, ETB, 작업·호스 연결 시점, 하역 구간, 작업 순서**, 제약을 충족하는 탱크 연계 등. 기존 데이터에 선박별 최종 배정값을 미리 고정하지 않음. 다만 `FIX ETB`는 변경 불가.
- 입력: 선박 및 물리 제원, ETA, 계약·NOR·Laytime, 11개 선석, 3개 통합 탱크, 외부 공정유량, 운영 제약, 고정 ETB.
- **Event-driven:** 유망 ETB 후보 생성·확장. 모든 연속시간을 전수탐색한다는 의미 아님.
- **Cost-aware CP-SAT:** 후보 집합에서 계약 체선료 직접 최소화.
- **Exact Inventory:** 탱크 수지·상하한·입출고 처리율을 CP-SAT 내부 제약과 독립 재생 검증에 반영.
- **Rolling Horizon:** 72시간 계획, 24시간 간격 재최적화·상태 승계.
- 후속 단계: 140항차 전체 기간 검증, 비용·성능 측정 및 웹 시각화. A/B/C, 리스크 분석은 별도 후속 목표이며 현재 체선료 최소화 검증을 대체하지 않음.
- `OPTIMAL`은 **생성된 유한 후보 집합**에 대한 증명으로 표기한다. 140항차 전체 기간 또는 연속시간 전역 최적성이라고 주장하지 않는다.

### 1.2 [확정/데이터 기준] V5 입력 규모

| 항목 | V5 기준 |
|---|---:|
| 항차 | 140건 |
| 독립 가상 선석 | 11개 |
| 유종별 통합 탱크 | 3개 |
| 6시간 단위 외부 공정유량 | 696건 |
| Hard FIX ETB | 15건 |

### 1.3 [확정] 시간과 회계 승계

- 72시간 계획창, 24시간씩 이동.
- ETA 기준 5시간 이내인 선박의 **기존 스케줄에 대한 동적 Lock** 정책 유지. 무조건적인 24시간 일괄 Freeze로 대체하지 않음.
- 운영자가 명시한 Lock/Unlock, FIX ETB, 기착·작업 시작 상태, 선석·작업 확정은 보호.
- 작업 중인 선박의 **잔여 화물량·탱크 재고·계약 정산 상태**를 다음 창으로 정확히 승계.
- 이미 하역한 물량을 재하역하지 않고, 이미 정산한 항차의 체선료를 중복 합산하지 않음.
- 서로 겹치는 72시간 계획창의 **예상 체선료를 단순 합산하지 않음**.

## 2. 선박·시간 용어 정의

| 용어 | 본 프로젝트에서의 의미 |
|---|---|
| `ETA` | 선박 예상 도착시각. 실제 도착 `ATA`를 알고 있다고 가정하지 않음 |
| `Direction` | 자료에 제시된 선석별 시간. 기본 접안 가능시각 계산에서 `ETA + Direction`에 사용 |
| `ETB` | 최적화가 계획한 접안시각. Hard FIX 항차는 고정 |
| `Work End` | 선박 하역·화물 이송 완료시각 |
| `Hose Disconnect End` | 호스 분리 완료시각 |
| `ETU` | **계획상 호스 분리 완료시점**. 별도의 이안 소요시간을 더하지 않는 시점 |
| `ATU` | 실제 선박 이안 시점. ETU 이후 현장 사정으로 늦어진 실제 시각이 있으면 ATU에 반영 |
| `Switching` | 직전 선박과 다음 선박 사이의 **교대 가능시각을 제약하는 선석별 기준시간**. 모든 선박에 독립 작업으로 무조건 생성하지 않음 |
| `POB / Last POB` | 도선사 승선 시각 / 마지막 승선 허용 시각. ETB와 같은 의미가 아님 |

### 2.1 [확정] 호스 분리 및 ETU

**모든 적용 대상 V5 선석의 계획상 기본 규칙:**

```text
하역 완료(Work End)
   → 호스 분리 2시간(고정)
   → 호스 분리 완료 = ETU
```

수식:

```text
Hose_Disconnect_End_A = Work_End_A + 2h
ETU_A = Hose_Disconnect_End_A
추가 Unberthing Duration = 0
```

예: **14:00 하역 완료 → 14:00~16:00 호스 분리 → 16:00 ETU.**

- ETU를 늦추기 위한 인위적인 60분 이안 시간은 **금지**.
- 실제 출항 지연·대기 정보는 ETU 변경이 아니라 ATU 등 실적에서 관리.
- **출항/이안은 24시간 가능**. 야간 도선 제한 때문에 ETU를 늦추지 않음.
- 선박 작업 완료 여부를 후속 선박용 Switching 종료시각으로 판단하지 않음.
- [구현 해석] 만약 다른 정책으로 실제 이안 가능 시각·출항 실적이 제시되더라도 본 **계획 ETU**에 자동 혼합하지 말 것.

## 4. 일반 선석: Direction·조건부 Switching 규칙

### 4.1 [확정] 판단은 실제 도착(ATA)이 아니라 ETA로 수행

선박 A = 해당 물리 선석에서 **직전에 배정된 선박**, B = 그 다음 선박.

```text
T_arrival_B = ETA_B + Direction_B
T_switch  = ETU_A + Switching_A(해당 선석 기준)
```

제공한 자료의 판단 조건:

```text
ETA_B + Shifting(Direction) ≤ 바로 직전 선박 ETU_A + Switching
```

### 4.2 [확정에 대한 구현 해석] 가장 빠른 ETB

**선박 A가 같은 물리 선석의 직전 선박일 때:**

```text
Earliest_ETB_B = max(T_arrival_B, T_switch)
```

- `T_arrival_B ≤ T_switch`이면 **A의 교대 제약이 후속 B를 제한하므로 Switching 적용**.
- `T_arrival_B > T_switch`이면 **교대 준비 기준시각이 이미 지났으므로 별도의 Switching 대기로 B를 지연시키지 않음**. B의 ETA + Direction 기준으로 접안 가능.
- A 이전 또는 B 이후에 해당 선석의 선박이 없으면 가상의 전후 Switching 작업을 생성하지 않음.
- 여기서 `max`는 **가장 빠른 ETB의 하한**. CP-SAT은 재고·운영상 제약에 따라 더 늦은 ETB도 선택할 수 있음.
- **A와 B의 선석 배정·순서는 CP-SAT의 결정**. 시설 참조명이 같은 다른 `berth_id`는 선행 선박이 아니다.

#### 예시 — BERTH-01 / #6

- A 하역 종료 14:00 → A ETU 16:00.
- #6의 Direction 1.5h, Switching 2.5h → `T_switch = 18:30`.

| B ETA | ETA + Direction | A ETU + Switching | 최소 B ETB | Switching에 의해 추가 지연? |
|---|---|---|---|---|
| 15:00 | 16:30 | 18:30 | 18:30 | 예 |
| 17:00 | 18:30 | 18:30 | 18:30 | 교대 경계에 일치 |
| 18:00 | 19:30 | 18:30 | 19:30 | 아니요 |
| 20:00 | 21:30 | 18:30 | 21:30 | 아니요 |

- `Direction`은 제공된 표의 선석별 시간으로 적용.
- **기존 코드의 고정 접안 60분을 선석별 Direction과 동의어로 자동 대체할지, 후보 시각만 조정할지**는 기존 Phase 모델과 도선 창을 함께 검토해 **중복 시간 가산이 발생하지 않게** 구현해야 함. 같은 구간을 두 번 더해서는 안 됨.

### 4.3 [확정] Switching은 선박의 고정 종료 Phase가 아님

- A만 선석을 사용하고 후속 B가 없는 경우: **Switching 블록 생성 불필요**.
- B가 상당히 뒤에 오는 경우 (`T_arrival_B > T_switch`): 교대 때문에 추가 지연되지 않음.
- **Switching은 A–B의 관계 및 실제 교대 제약을 나타냄**. 개별 A의 `work_end → ETU`에 Switching을 추가하지 않음.
- 선박 A의 완료 판정은 `ETU_A`와 필요한 계약·재고·작업 정산 상태로 수행. `switching_end_at`이 완료를 지연시키면 안 됨.
- 웹에서는 후속 교대가 실제로 적용되는 경우에만 Switching을 표시. 표시에는 A→B 식별자, 기준 ETU, 교대 허용시각을 포함하는 것이 적절함.

## 5. #4-1·#4-2 특례: BERTH-07 및 BERTH-08

### 5.1 [확정] 물리 관계

- `BERTH-07 = #4-1`, `BERTH-08 = #4-2`.
- **서로 다른 독립 선석이지만 인접한 특례 대상 선석 2개**.
- 여기서의 중첩 접안은 **두 선박이 같은 선석을 동시에 점유하는 것이 아니라, A가 #4-1에 남아 있을 때 B가 #4-2에 이미 접안할 수 있는 것**을 의미.
- 선석 07/08과 중복 시설명 매핑(#1,#8)을 혼동하지 않음.

### 5.2 [확정] GRT 조건과 동시 접안

- 두 선박 **모두 GRT ≤ 3,000**이면 #4-1/#4-2 사이에 **특례 중첩 접안 허용**.
- 둘 중 하나라도 **GRT > 3,000**이면 #4-1/#4-2의 **동시 접안 상태 불허**. 일반적인 순차 접안 규칙 적용.
- 별개의 물리 선석이라는 사실과 **특정 선박 조합에만 적용되는 동시 점유 제한**은 양립한다.

### 5.3 [확정] 2시간은 *최대치가 아니라 정확히 고정된 시차*

특례 중첩 접안을 선택한 경우:

```text
ETU_A = Work_End_A + 2h
ETB_B = ETU_A - 2h
따라서 ETB_B = Work_End_A
```

예시:

| 사건 | 시각 |
|---|---|
| A 하역 완료 / B 접안(ETB) | 14:00 |
| A 호스 분리 | 14:00~16:00 |
| A 호스 분리 완료 = A ETU | 16:00 |
| B가 호스 연결을 **시작할 수 있는 가장 빠른 시각** | 16:00 |

- A가 호스 분리 중이어도 **B는 인접 선석에 접안 가능**.
- 그러나 **A 호스 분리 완료 전 B 호스 연결 불가**.
- **A와 B의 동시 하역은 무조건 금지**.
- 4-1·4-2 중첩 특례에 대해 일반 Switching 시간을 **추가로 중복 가산하지 않음**.
- 후속 B가 실제 ETA·Direction 조건상 `ETU_A - 2h`에 도착할 수 없다면 **특례를 강제로 적용하지 않고 일반 순차 접안**을 허용.
- [구현 해석] 동시 접안 가능성은 `ETA_B + Direction_B ≤ ETU_A − 2h` 및 다른 물리·도선 제약도 충족할 때만 인정. B의 ETA를 실제 도착시각처럼 임의 변경하지 않음.

### 5.4 [확정] 큰 선박 또는 특례 미사용 시

- GRT 조건을 충족하지 않으면 **동시 점유 불가**, 일반적으로 **A ETU 이후** B 접안 가능.
- 두 선박 모두 작은 선박이어도 접안 시점이 맞지 않으면 **일반 순차 접안 가능**.
- 일반 순차 교대에서 적용할 #4 선석 수치는 **Direction 1h, Switching 1h**.

### 5.5 [확정된 자원 제약 — 범위 제한]

- **공동으로 사용할 수 없는 작업:** 두 선박의 동시 하역, A 호스 분리와 B 호스 연결의 동시 사용.
- **허용:** A 호스 분리와 B의 인접 선석 접안은 동시에 가능(두 선박 모두 GRT ≤ 3,000인 특례 조건).
- 접안 작업 공간의 제한은 **위 두 선석의 동시 접안 규칙**으로 반영하되, 이로부터 다른 선석의 공통 장비 제약을 추론하지 않음.
- `BERTH-07`과 `BERTH-08` 각 선석 자체의 동일 선석 점유 중복은 별도로 금지.

## 6. 야간 도선 및 접안 제한

### 6.1 [확정] 접안과 ETU/출항을 구분

- 야간 **접안/도선** 제약은 적격 선박의 ETB/POB 후보를 제한.
- **ETU는 24시간 가능**하고, 출항 도선 때문에 ETU를 미루지 않음.
- **02:00 이상~08:00 미만** 제한 대상 접안은 해당 구간을 피해서 **08:00 이후**로 연기.
- 단, 도선사의 일출·일몰/Last POB 조건과 다른 제약도 동시에 충족해야 하므로 **항상 08:00이 곧 유효 ETB라는 뜻은 아님**.

### 6.2 [사용자 제공 자료] GRT 및 Last POB

| 구분 | 제공된 내용 |
|---|---|
| GRT 30,000 미만 | 일반적으로 야간 도선 제한 없음 |
| GRT 30,000 이상~50,000 부근 | Last POB = 일몰 1.5시간 전 |
| GRT 50,000 이상 | Last POB = 일몰 2시간 전 |
| GRT 75,000 이상 | 별도 야간 도선 제한 조건에 명시 |
| GRT 30,000 이하 **수입선** AND Draft ≥ 10.5m | 별도 야간 도선 제한 조건에 명시 |
| GRT 30,000 이상 | 제공 자료에서 `ETA + Direction` 또는 `직전 ETU + Switching` 시각의 02:00~08:00 구간 판정 제시 |

- `Last POB`는 일몰 및 GRT를 근거로 계산한 도선사 승선 경계로, ETA/ETB와 혼동하지 않음.
- GRT 30,000 및 50,000 **정확한 경계값에서 표기 겹침**이 있어 코드의 `>=`, `>` 선택 전 출처 규칙 우선순위 확인 필요.
- 사진에 나오는 `GRT ≥ 75,000 OR (GRT ≤ 30,000 AND 수입 AND Draft ≥ 10.5)` 조건과 `ETA ≥ Last POB`, `02:00~08:00` 조건 사이의 **정확한 AND/OR 결합·적용 순서**는 이미지 문맥만으로 완전히 확정할 수 없음. 임의로 단일 Boolean 식을 만들지 말 것.
- 따라서 **미확정 조합에 영향을 받는 후보는 `UNSUPPORTED_OPERATIONAL_POLICY`로 차단**하거나 추가 정책 확인 후 활성화. 무근거로 자동 08:00 접안을 승인하지 않음.

### 6.3 [구현 요구] 접안/도선 정책

- `ETA + Direction`, ETB 후보, `POB`, Last POB 사이 관계를 일관되게 적용.
- **야간 출항 규제 창을 ETU에 강제하지 않음.** 이안 운항 자료를 무시하자는 뜻이 아니라 본 스케줄링에서 ETU 지연변수를 두지 않는다는 의미.
- 과거 V5 코드의 별도 출항 도선창 필수 조건은 위 확정 규칙과 비교 후 교체하되, 접안에 필요한 근거는 보존.

## 7. 호스·작업·재고 계산 규칙

### 7.1 [확정] 작업 단계 및 시간 관계

```text
ETA
  → Direction을 고려한 접안 가능시각
  → ETB (최적화)
  → 호스 연결 (이전 선박의 호스 분리·공유 설비 제한 확인)
  → 작업/하역 (실제 허용 작업구간에 따라 분할 가능)
  → Work End
  → 호스 분리 2시간(고정)
  → ETU
```

- 업무 정지·금지 작업시간이 있으면 실제 `work_intervals`를 여러 조각으로 모델링.
- **호스 연결시간 자체**는 이번 대화에서 2시간으로 새로 확정한 적이 없음. 기존 코드의 합성 120분 정책과 **호스 분리 고정 120분을 혼동하지 말 것**. 호스 연결시간의 최종 정책은 기존 검증된 입력·정책을 확인한 뒤 별도 기록.
- 별도의 보라색 **이안 Duration 막대 제거**. ETU는 점·마커로 표시.
- Switching은 후속 선박과의 교대 조건이 실제로 성립할 때만 관계 이벤트로 표기.

### 7.2 [확정] 탱크 및 유량

- **3개 유종별 통합 탱크**와 외부 공정유량은 입력에서 고정 제공.
- 외부 공정유량은 최적화가 임의로 증감시키는 결정변수가 아님.
- 시간별 수지: `재고(t) = 초기 재고 + 누적 입고 − 누적 출고`.
- 재고 상·하한, 유종·탱크/선석 호환, 입고·출고 처리율, 외부 공정유량 변경 경계를 정확한 정수·유리수 계산으로 검증.
- 하역은 선박별 작업구간에 맞게 재고에 반영. 재고 위반 방지를 위해 물량을 몰래 삭제·추가하거나 화물군을 바꾸지 않음.
- 72시간 창 이월 시 원본 화물량 보존, 완료·잔여 화물량, 초기·종료 재고 연속성이 유지되어야 함.

### 7.3 [확정] 계약 비용·출력

- 계약 체선료는 작업시간/ETA만의 단순 대기 비용이 아니라 **계약상 Laytime/NOR/예외/정산 정책**으로 산정.
- 체선료는 가능한 한 **정수 센트**로 직접 최소화하며, 계약별 정산이 미해결인 경우 임의의 0 비용으로 대체하지 않음.
- 최종 출력에 각 항차 `ETA, ETB, Work Start/End, Hose Disconnect End, ETU, berth_id, work_intervals, 비용, 재고`, 후보 탐색/최적성 상태를 포함.

## 9. 구현 검증 시나리오 (Acceptance Criteria)

다음은 완료 기준이다. 단위 테스트뿐 아니라 **CP-SAT 결과와 독립 검증기의 일치**를 확인해야 한다.

### A. ETU 및 호스 분리

1. `Work End 14:00` → `Hose Disconnect End 16:00` → `ETU 16:00`.
2. 추가 `unberthing_seconds`가 ETU에 누적되지 않음.
3. 야간 02:00에 호스 분리가 끝나도 ETU가 야간 때문에 밀리지 않음.
4. Switching 완료가 선박 A의 완료 판정을 지연시키지 않음.

### B. 일반 선석 Switching

5. A→B 교대가 실질적으로 접안을 제한할 때만 Switching 적용.
6. `ETA_B + Direction_B > ETU_A + Switching`이면 Switching으로 인한 추가 지연 없음.
7. 후속 선박이 없으면 Switching 막대·가짜 일정 미생성.
8. 선박 B의 ETB를 CP-SAT이 더 늦게 잡아도 기존 조건의 위반·비용을 정확히 재검증.
9. `BERTH-04`/`05` 및 `BERTH-03`/`11`은 중복 참조명과 무관하게 독립 점유 가능(다른 명시된 물리제약은 제외).

### C. 4-1·4-2

10. 둘 다 GRT ≤ 3000: `A ETU=16:00`, `B ETB=14:00`, A 호스 분리 14~16, B는 14시에 인접 선석 접안 가능.
11. B의 호스 연결은 **16:00 이전 금지**, 두 선박의 동시 하역 금지.
12. 둘 중 하나라도 GRT > 3000: #4-1/#4-2 동시 점유 금지.
13. 소형 2척이라도 중첩 시점이 성립하지 않으면 순차 접안 허용.
14. 특례 중첩에 일반 Switching을 중복 가산하지 않음.
15. 같은 `berth_id` 자체의 중복 선박 점유는 금지.

### D. 도선·최적화·Rolling

16. 제한 대상 02:00~08:00 접안 후보를 거부하고 허용시간 후보만 제공.
17. Last POB 조건을 ETB와 혼동하지 않고, 미확정 GRT/흘수 경계는 실패로 보고.
18. ETA/Direction 기준을 사용하고 ATA를 추정 생성하지 않음.
19. FIX ETB 15건 유지, 140항차 입력 범위 검증, 탱크 재고·처리율 재생 검증.
20. 72h/24h Rolling에서 ETU·선석·호스 상태·잔여 물량·비용 승계, Checkpoint 재개 일치.
21. 구형 규칙으로 만든 Checkpoint를 신규 정책 Checkpoint로 잘못 취급하지 않음.
22. UI 간트차트 단계·색상·ETU 마커가 실제 결과 JSON과 일치.
23. 3척→5척→10척 등 소규모부터 테스트하고 전체 140항차의 성공·전역 최적성을 섣불리 주장하지 않음.

## 10. 아직 명세로 확정하지 않은 항목 (구현 중 임의 가정 금지)

1. **호스 연결 소요시간:** 기존 합성 정책에서 120분을 사용했지만, 이번 대화의 **2시간 고정 확정은 호스 분리**에 대한 것. 호스 연결 시간의 실제 정책·근거는 별도로 확인.
2. **Direction과 접안 Phase의 정확한 시간 표현:** `ETA+Direction` 하한과 기존 `berthing_seconds`가 동일 시간을 의미한다면 **중복 가산 금지**. 도선·접안 Phase 세부 순서를 코드에서 한 번만 반영할 필요.
3. **야간 도선 특수 조건의 Boolean 조합·경계:** GRT 정확히 30,000 / 50,000, 75,000 이상 및 저GRT·깊은 흘수 수입선의 동시 조건, `ETA≥Last POB`와 02~08 규칙의 결합 순서. 확인되지 않은 경우 안전하게 차단.
4. **4-1·4-2 이외의 추가 공유설비:** 단순 참조 시설명 중복에서 유추하지 않는다. 별도의 출처 기반 제약만 허용.
5. **실제 측정치와 합성 가정의 구별:** V5 원본 전체를 사용자 제공 자료와 대조해 값의 출처·검증 상태를 남겨야 함.
