# Phase 3 — source-backed facility master (initial work)

Base `d4af552` on branch `feat/v2-phase3-operational-constraints`. The Phase 2 follow-up commit is on a separate unmerged feature branch; it is not included in this base. The source workbook itself was not available for inspection. The pre-existing `data/sk_facilities.json` identifies the original workbook, its recorded SHA-256, worksheet and row for each of 22 facilities. Those records are an extraction, not an independent re-verification of the absent workbook; source conflicts and missing information remain visible.

`build_facility_master(path, active_facility_codes=...)` loads a supplied schema-v1 file, requires explicit active choices, validates codes and duplicates, returns selected source rows and the hash of the exact file bytes. It never chooses the existing eight virtual berths, never assumes an 8- or 11-facility limit, never changes the production database and grants no operational approval. A future replacement can be supplied as another compatible file; the file hash changes and identifies the source revision. Mapping of virtual berths, tug requirements, pilotage, switching, FIX, cross-berth overlap and tank connections remain pending. The function is a separate opt-in read-only component, not wired to scheduling.
