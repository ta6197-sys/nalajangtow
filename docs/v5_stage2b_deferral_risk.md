## 실행

프로젝트 저장소에서 새로운 브랜치를 만든 다음, ZIP 압축 해제 폴더를 가리켜 실행:

```bash
python /path/to/unpacked/apply_to_repo.py --repo .
python /path/to/unpacked/apply_to_repo.py --repo . --apply
git diff --check
git diff --stat
```

기본 실행은 **파일을 변경하지 않습니다.** `--apply`는 모든 고유 앵커를 검증한 뒤 변경합니다. 최신 main이 달라졌다면 중단하며 Codex가 수동 충돌 해결해야 합니다. 작업 트리는 깨끗해야 합니다.

## 명시적 실행 설정

현재 신규 실행 JSON에 다음 두 필드를 추가합니다. **기존 파일을 덮어쓰지 말고 별도 복사본을 만들어야 합니다.**

```json
{
  "inventory_policy_version": "V5_PHYSICAL_BOUNDS_OPERATING_WARNINGS_V1",
  "inventory_risk_policy_version": "V5_INVENTORY_RISK_20_80_10_90_V1",
  "deferral_policy_version": "V5_ROLLING_SAFE_ADMISSION_V1",
  "max_deferral_probes": 8
}
```

위 항목은 기존 `config/v5_balanced_ext_20270109.example.json`의 다른 필드를 **유지한 상태로 추가**하는 항목입니다. 단독 네 필드 JSON은 실행 가능한 전체 설정이 아닙니다.

## 역할 분리와 한계

- Stage 2A `operational_warnings` 10–95% 체계는 과거 호환성을 위해 보존합니다. 신규 `inventory_risk_v1`은 20–80% 정상/10·90% 심각 기준으로 독립 출력되며, 충돌이 아니라 서로 다른 정책 버전의 결과입니다. 대시보드에 어떤 등급을 보여주는지는 신규 위험도 버전을 선택해야 합니다.
- 이월 알고리즘은 **전역 최적성을 증명하지 않습니다.** 전체 선박이 유한 후보 영역에서 INFEASIBLE로 반환될 때만 최대 8개의 별도 부분집합 후보를 탐색하는 보수적 기능입니다. 정책 누락·시간 초과·검증 미해결은 이월로 바꾸지 않고 중단합니다.
- `window_demurrage_cents`는 **이번에 인정된 선박의 후보 비용**입니다. 제외된 선박의 체선료가 0이라는 의미가 아니며, 전체 비용 확정에는 모든 계약의 정산 가능 여부를 별도로 확인해야 합니다.
- 5시간 자동잠금은 이미 존재하는 이전 일정 및 운영자 승인 일정에 그대로 적용합니다. 단, 신규 모드에서는 원래 일정이 없던 선박을 이전 약속으로 오인하지 않습니다.
- `48h/2회`는 경고 기준이지 강제 배정이나 물리적 제약이 아닙니다. 기존 전체 최적화의 우선 시도와 늦은 ETA 선박부터 제외하는 절차로 기아 위험을 낮추지만, 무기한 이월을 수학적으로 불가능하게 만드는 상한 정책은 아닙니다.
- 재고 위험도는 V5 독립 검증의 이벤트 시점 재고를 사용하며, 연속 체류시간이나 임계값 사이 정확한 통과 시각을 계산했다고 주장하지 않습니다.
